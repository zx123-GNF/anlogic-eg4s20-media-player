## 2. 系统架构

### 2.1 时钟域（与 M1/M2 完全一致，**没有新增**）

| 时钟 | 频率 | 用途 | M3 新增内容 |
|---|---:|---|---|
| `clk_50m` | 50 MHz | KEY2 同步、两个 PLL 的参考 | 无 |
| `pixel_clk` | 25.000 MHz | 光栅 / AXIS / 页控制 / HDMI 核 / 读 FIFO | **按键消抖、长按、暂停、轮播计时、数码管扫描与译码、595 移位** |
| `serial_clk` | 125.000 MHz | 4 路 TMDS 串行器 | 无 |
| `sdram_clk` | 100.000 MHz | `Sdram_Control_4Port`、SD SPI、FAT32 FSM、写页器 | 仅 `m3_fat_bmp` 多两个只读状态输出（`O_key`/`O_has_img`），无新增逻辑 |
| （未约束）`spi_clk` | 50 MHz / 0.8 MHz | SD 引擎内部分频 | 无（M2 R1 的已知限制） |

> **为什么把 M3 的逻辑全放在 25 MHz 域**：这正是本任务"新增逻辑尽量放低速域"的要求。
> 唯一与 100 MHz 域打交道的，是"图号/总数/错误码"这种**准静态**状态，跨域代价极低（见 §5.4）。

### 2.3 关键设计决定及其理由

| # | 决定 | 理由 |
|---|---|---|
| 1 | **按键动作在"松开"时生效**（M2 是"按下"立即生效） | 只有"松开"这一时刻才能区分短按与长按；否则长按必然先切一张图再暂停 |
| 2 | **长按挂在 KEY0 上，KEY1 不做长按** | KEY1 只用于"上一张"，按住不放也只走一张，不会把轮播暂停掉——演示时不会误触 |
| 3 | **轮播计时用帧计数，不用毫秒计数** | 3 s 用 25 MHz 计数要 27 位；用帧计数只要 8 位，且板级时钟有 ±50 ppm 误差也不影响"每张 3 秒"的观感。1 帧 = 800×525/25 MHz = **16.800 ms** |
| 4 | **计时器在"装载完成"时重装** | 这样"每张图完整显示 3 s"是指**上屏时间**，装载的 0.4 s 不占用它；代价是墙钟周期 ≈ 3.0 + 0.4 ≈ 3.4 s（§5.3 有精确时间轴） |
| 5 | **长按期间不产生切图** | `S_hold_done` 会吞掉本次松开；模型 §8 检查 2 逐条验证 |
| 6 | **无图（`count==0`）时禁止自动轮播** | 否则空卡会每 3 s 触发一次"重试挂载 + 2.7 s 超时 + 重写图案"，屏幕一直闪；保持 M2"按键才重试"的行为 |
| 7 | **数码管内容全部在 25 MHz 域决定**，100 MHz 只提供状态 | 避免在高速域加逻辑（M2 的 100 MHz 余量只有 0.155 ns），也避免把扫描时钟引入高速域 |
| 8 | **595 用"锁存后整帧移位"的驱动**，不用厂商那个自由运行的版本 | 厂商 `HC595_Driver.v` 每个时钟都把 `Data` 重新装进移位寄存器，一帧移一半时数据变化会把新旧字混在一起（表现为切图瞬间闪一下）。M3 在 `I_start` 那一拍整字锁存，整帧移完再 `RCLK`，不会出混字 |

## 3. 状态机

### 3.1 交互状态机（`m3_video_src.v`，25 MHz）

M3 没有另起一个大状态机，而是在原有的"光栅 + 页控制"旁边加了一个**并行的按键/计时进程**。
它与主控 FSM 的耦合只有三根 1 bit 翻转线（next / prev / ready）和一根 `has_img` 电平。

```
                    ┌──────────────── 每个 25 MHz 时钟 ────────────────┐
  KEY0_n ─2FF─┐     │                                                  │
              ├─ 消抖(2^18) ─┬─ press ─> hold_cnt=0, hold_done=0        │
  KEY1_n ─2FF─┘              │                                          │
                             ├─ 按住 且 !hold_done:                     │
                             │      hold_cnt >= 25e6-1 ?                │
                             │        是: hold_done=1, paused^=1,      │
                             │            pause_ev=1（长按在 1.000 s 触发）│
                             │        否: hold_cnt++                    │
                             └─ release ─┬─ KEY0 且 !hold_done ─> next_pulse
                                        └─ KEY1 ───────────────> prev_pulse

  帧起始(vstart) ─┬─ play = !paused && has_img
                  ├─ auto_fire = vstart && play && (auto_cnt >= 178)
                  └─ timer_rst = ready_pulse | next_pulse | prev_pulse
                                 | pause_ev | auto_fire
                       auto_cnt: timer_rst ? 0 : (vstart ? min(auto_cnt+1,178) : 保持)

  next_ev = next_pulse | auto_fire  ──> kn_tog ^= 1     （送 100 MHz 域，异或边沿）
  prev_pulse                        ──> kp_tog ^= 1
```

对应到"任务要求的状态机"：

| 要求的状态 | M3 里的实现 |
|---|---|
| `IDLE` | 主控 FSM 的 `S_KEY`（100 MHz）+ 25 MHz 域的"等按键/等轮播到点" |
| `SCAN` | `S_SEL` → 串行 min/max 扫描（M2 原样） |
| `LOAD` | `S_HDR … S_DEND`（≈0.4 s，**此时只有 `S_inload`/`S_wr_busy` 在动，按键翻转无效**） |
| `SWAP` | `S_SW0/S_SW1/S_SHOW`（ready 翻转 + 25 MHz 域在场消隐换页） |
| `IDLE`（回） | 回到 `S_KEY`；轮播计时器已在 `ready` 时重装 |

### 3.2 装载期间忽略按键的机制（为什么不用额外逻辑）

`m3_fat_bmp.v` 里按键是**异或边沿检测**：

```verilog
S_kn_s <= {S_kn_s[1:0], I_key_next_tog};        // 3FF 同步
wire S_key_next = S_kn_s[1] ^ S_kn_s[2];        // 1 拍脉冲
...
S_KEY: begin ... else if (S_key_next) begin ... end   // 只在 S_KEY 里看
```

所以装载中到来的翻转只改变 `S_kn_tog` 的**电平**，产生的那 1 拍脉冲落在非 `S_KEY` 状态，
**被丢弃而不是排队**（这正是任务要求的"装载期间忽略按键"）。

- 自动轮播同理：计时器在 `ready` 时归零，3.007 s 远大于 0.4 s 装载，边沿不会落在装载窗口里。
- 模型 §8 检查 4 用一个"装载 400 拍 + 5 次连按"的场景验证：**只走 1 张，其余 4 次被丢弃**。

### 3.3 上电时序（与 M2 相同，只是多了一个显示）

```
KEY2 释放 & PLL 锁 ──> pixel 域起振（数码管先显示 "--"，因为状态还是 0）
  ├ 1.31 ms 后 → 100 MHz 域复位释放 → SDRAM 控制器初始化 240 µs
  ├ 10 ms → CMD0/CMD8/CMD55/ACMD41（无卡时 2^28 拍 = 2.68 s 超时 → err=1 → 数码管 "E1"）
  ├ MBR/BPB/根目录扫描（3 次挂载扇区 + 目录扫描 ≈ 1 ms）→ err=3 时数码管 "E3"
  ├ 选图 + BMP 头校验 + 逐扇区读（约 0.39 s）→ 写页 → ready
  └ 25 MHz 域在场消隐换页 → 数码管在 ready 那一拍把图号锁存上屏
```

## 4. 按键：消抖、短按、长按

### 4.1 消抖（沿用 M2 的滤波器）

```
2FF 同步（异步按键 -> 25 MHz）→ 计数到 2^18-1 = 262 143 才认一次电平变化
→ 262 144 × 40 ns = 10.49 ms
```

`S_key_stb[k]`：1 = 松开、0 = 按下（已消抖）；`S_key_press = stb_d & ~stb`、`S_key_rel = ~stb_d & stb`。

### 4.2 长按

- 阈值 `HOLD_CLKS = 25 000 000` → **1.000 s**（25 位计数器，从消抖后的按下沿算起；物理按下到判定 = 10.49 ms + 1.000 s）
- 到达阈值的那一拍：`paused ^= 1`、`pause_ev = 1`、`hold_done = 1`（立即反馈，不必等松手）
- `hold_done` 只在下次按下时清零，因此**长按松手不会再切一张**（模型 §8 检查 2 验证 `n_next == 0`）

### 4.3 映射表（写进报告的就是最终实现的）

| 按键 | 操作 | 动作 | 生效时刻 |
|---|---|---|---|
| KEY0 (F7) | 短按 < 1.000 s | 下一张（编号升序，末尾回绕到最小） | 松开时（消抖后） |
| KEY0 (F7) | 长按 ≥ 1.000 s | 自动轮播 暂停 ⇄ 恢复 | 按下满 1.000 s 时 |
| KEY1 (E7) | 短按 / 长按 | 上一张（编号降序，开头回绕到最大）；长按也只走一张 | 松开时 |
| KEY2 (H14) | 按下 | 整芯片异步复位（同步释放），M2 原样 | 立即 |
| — | 无卡时按 KEY0/KEY1 | 重新走一遍挂载流程（M2 行为） | 松开时 |

> 备选方案（报告里说明，未采用）：把暂停放到 KEY1 长按，或"双击 KEY0"。前者的缺点是
> "按住上一张"会误暂停，后者的缺点是双击与切图共用按键、手感差。**长按 KEY0 是唯一不
> 与任何常用操作冲突的选择。**

## 5. 自动轮播时序

### 5.1 时间基准

| 量 | 值 | 推导 |
|---|---|---|
| 像素时钟 | 25.000 MHz | `pll_m3_hdmi` C1（M0 已实测） |
| 一帧 | 800 × 525 = 420 000 拍 = **16.800 ms** | 帧率 59.52 Hz |
| 每张 | `AUTO_FRAMES = 179` 帧 = **3.0072 s** | 179 × 16.800 ms |
| 长按 | 25 000 000 拍 = **1.000 s** | 25 MHz |
| 消抖 | 262 144 拍 = **10.49 ms** | 25 MHz |

选 179 帧的理由：3.000 s / 16.800 ms = 178.57，取整 179 → 3.0072 s（误差 +0.24%）。
计数器只要 8 位（0..178），比毫秒计数器省 19 个 FF，而且**与时钟精度无关**。

### 5.2 计时器的五个重装事件

```
timer_rst = ready_pulse   （一张图装载完成、即将上屏）
          | next_pulse    （手动下一张，松开时）
          | prev_pulse    （手动上一张）
          | pause_ev      （暂停/恢复，恢复后不会"立刻跳一张"）
          | auto_fire     （自动走一张后立即重新起算）
```

第 5 条是本次做模型时**发现并修掉的一个真问题**：最初 `auto_fire` 不在重装列表里，
于是轮播到点后计数器停在 178，装载的 0.4 s 里**每一帧都会再发一次 next 翻转**
（虽然都被忙状态丢弃、功能上看不出来，但毫无必要，而且给"边沿恰好落在 `S_KEY`"留下了窗口）。
修法是一行：把 `S_auto_fire` 或进 `S_timer_rst`（`rtl/m3_video_src.v`）。
模型 §8 检查 3 的"auto step restarts the timer itself"就是盯这一条。

### 5.3 一段稳态时间轴（假设 3 张图、正在播放）

```
t=0         ready（第 1 张上屏）→ 计时器归零，数码管锁存 "0001"
t=0…3.007   显示第 1 张
t=3.007     auto_fire → kn_tog 翻转 → 100 MHz 域 3 拍同步后进 S_KEY 看到脉冲 → 扫描选图
t=3.007…3.4 仍在显示第 1 张（装载期，数码管 DP 常亮；期间按键无效）
t≈3.4       ready → 场消隐换页，第 2 张上屏；数码管 "0002"；计时器归零
...
```

### 5.4 手动与自动共存

| 场景 | 行为 |
|---|---|
| 播放中按 KEY0 | 立即切下一张；计时器在"松开"和"新图 ready"各归零一次 → 新图仍有完整 3 s |
| 播放中长按 KEY0 | 暂停，计时器归零并冻结（`play=0` 时不累加）|
| 暂停中按 KEY0/KEY1 | 照常切图，**仍然是暂停状态**（便于单张讲解）|
| 暂停中长按 KEY0 | 恢复；计时器从 0 起算，不会立刻跳下一张 |
| 无卡 / 无 BMP | 不轮播（`has_img=0`），数码管 `E1`/`E2`/`E3`，按 KEY0/KEY1 重试挂载 |
| 卡里有 BMP 但全部不合格 | 每 ≈3.4 s 重试一轮（重写同一张回退图案，页面内容相同 → 画面看不出变化），数码管 `E4`；按 KEY0/KEY1 立即重试 |

### 5.5 时间参数怎么改

| 想改 | 改哪里 | 重编译 |
|---|---|---|
| 每张秒数 | `m3_video_src` 的 `AUTO_FRAMES`（= 秒数 / 16.8 ms） | 70 s |

## 6. 数码管

### 6.1 硬件事实（先纠正一处前提）

任务书写"两片 595 只有 8 位 = 2 位数字可用"。按 `docs/research/hw-facts.md` §8（管脚表 97–99 +
底板图 `74hc595`×2、`smg_6*8`×2）与厂商 `HEX8.v`（8 位循环移位 + 8 位段码）：

> **16 bit = 段选 8 + 位选 8，是 8 位数字**，不是 2 位。

因此 M3 把 8 位全扫，只用其中 6 位：**右边 4 位显示图号、最左 2 位显示总数**，中间 2 位留空。
即使底板上只焊了 2 位（右端），也能看到图号的低 2 位（`01` 这种），**两种硬件都能给出可读信息**。

### 6.2 帧格式与扫描

```
   一帧 16 bit = {seg[7:0], sel[7:0]}，MSB 先出
   ┌ seg[7] = DP（低有效），seg[6:0] = g f e d c b a（低有效）
   └ sel[7:0] = 位选，一次只亮一位（高有效）

   扫描：25 MHz / 25000 = 1 kHz 扫描节拍
        每个节拍点亮下一位 -> 每位 1 ms -> 8 位一帧 8 ms（刷新 125 Hz，无闪烁）
        SCLK = 25 MHz / (2×5) = 2.5 MHz，16 bit = 170 拍 = 6.8 µs（占 1 ms 时隙的 0.7%）
```

一帧的时序（`m3_hc595.v`）：

```
IDLE --start--> PRE(DIO=b15, SCLK=0) --(5 拍)--> HI(SCLK=1) --...  16 次
                                              └--> LATCH(RCLK=1) --(5 拍)--> LEND(RCLK=0) --> IDLE
```

数据在 `I_start` 那一拍**整字锁存**（不是厂商那种"每拍从 Data 重装"），所以移位期间
即使数码管内容变了也不会出现新旧混字；下一个 1 kHz 节拍才装载新内容。

### 6.3 显示内容与布局

```
 位:   d7   d6   d5   d4   d3   d2   d1   d0
       └─总数─┘   空   空   └──── 图号（IMGnnnn）────┘
 例:    0    3               0    0    0    1        <- 3 张图，正在放 IMG0001
```

| 状态 | d7..d0 | 说明 |
|---|---|---|
| 正常 | 总数(2 位) + 空 + 空 + **图号 4 位十进制（补零）** | 图号取自文件列表的 key（`IMGdddd` 的 4 个十进制数字，**每个半字节一个 BCD 位，不需要二进制→BCD 转换**） |
| 文件名不是 `IMGdddd` | 同上，图号改为"列表序号+1"（如第 10 张 → `0010`） | `O_key == 0xFFFF` 时的回退 |
| 正在装载 | 图号 d0 的 **DP 常亮** | 对应 `m3_page_wr` 的 `O_busy`（约 0.4 s） |
| 暂停 | 整屏 **~1.95 Hz 闪烁**（1 kHz/2^8 的高低电平各 0.256 s） | 一眼看出"停在暂停" |
| 无卡 / 卡坏 | `E1`（初始化/读超时） | `O_err = 1` |
| 不是 FAT32 / 挂载失败 | `E2` | `O_err = 2` |
| 卡里没有 `*.BMP` | `E3` | `O_err = 3` |
| 有 BMP 但全部不合格（回退图案） | `E4` | `O_err = 4` |
| 上电后还没出第一张图（≈0.5 s）/ 还在挂载 | `--` | 复位后还没有任何一页完成（`S_have_num = 0`），或 `err = 0` 且 `count = 0` |
| 图被截断（err=5）/ 文件偏短（err=6） | **仍显示图号**（图确实上屏了） | 错误看 LED2 |

### 6.4 段码表（低有效，与厂商 `HEX8.v` 的 `decode` 完全一致）

| 字符 | seg[6:0] | 字符 | seg[6:0] |
|---|---|---|---|
| 0 | `1000000` | 5 | `0010010` |
| 1 | `1111001` | 6 | `0000010` |
| 2 | `0100100` | 7 | `1111000` |
| 3 | `0110000` | 8 | `0000000` |
| 4 | `0011001` | 9 | `0010000` |
| E | `0000110` | `-` | `0111111`（只有 g 段） |

DP 是 `seg[7]`，0 = 亮（与段码同极性）；空白 = `8'b1111_1111`（所有段+DP 全灭）。

### 6.5 位序假设与 `DIG_REV` 开关键

厂商 `HEX8.v` 的约定是 `sel = 8'b0000_0001` 时显示 `disp_data[3:0]`（最低半字节），
M3 沿用这个约定：**`sel[0]` = 最右边（个位）数字**。

上板如果发现数字是**左右镜像**（`0001` 显示成 `1000`），说明底板的 595 到数码管的
位选是反着接的——把 `m3_seg7` 的 `DIG_REV` 从 0 改成 1（一行参数，70 s 重编译），
选择线镜像，显示内容不变。

### 6.6 多位状态总线的跨域（29 bit）与"证据"式过滤

`mounted/err/count/index/key` 都在 100 MHz 域，一起变化时**所有位在同一拍翻转**，
2FF 采样可能采到"旧值低位 + 新值高位"的混合值。M3 的做法：

```
2FF 同步 → 每 1 kHz 采样一次 → 只有"连续两次采样完全相同"才被接受
```

为什么这样就**不可能**显示错值：混合值只可能出现在源变化的那个 100 MHz 拍之后
**1 个 25 MHz 周期（40 ns）**内，40 ns 过后所有位都已是新值；而滤波器要求
"相隔 1 ms 的两次采样相同"——40 ns 的瞬态不可能跨过两个 1 kHz 采样点。
代价是显示最多滞后 2 ms（人眼不可见）。模型 §8 检查 5 用"单点毛刺 + 撕裂值"两种
序列验证了这一点。

图号另外在 `ready_pulse` 那一拍**锁存**，所以"数码管上的号"永远等于"屏幕上那张图"
（装载期间显示的是旧图号 + DP 常亮，不是新目标号）。

## 9. 上板验证清单

> 前提：`m3_interact.bit` 用 TD Board Debugger / `bw.exe` 经 JTAG 下载；
> TF 卡是 **FAT32**、根目录有 `IMG0001.BMP`…（`tools/make_bmp.py` 生成）。
> 建议至少准备 3 张图，编号不连续更能看出"按编号排序"（例如 `IMG0001/0003/0007`）。

### 9.1 按哪个键应该看到什么

| # | 操作 | 预期现象 |
|---|---|---|
| 1 | 插卡上电 / 按 KEY2 | 先黑屏 ≈0.5 s，然后出现编号最小的那张；数码管左边显示总数（如 `03`），右边显示它的图号（如 `0001`）；`led[0]` 常亮 |
| 2 | 不碰按键，掐表 3 s | **约 3.0 s（+0.4 s 装载）** 自动切到下一张，数码管跟着变 `0003`；装载的那 0.4 s 里数码管图号是**旧图号 + 末尾 DP 常亮**（新图号在 ready 时才跳） |
| 3 | 观察 10 s | 3 张图循环播放，节奏稳定，无撕裂、无闪烁；数码管刷新无可见闪动 |
| 4 | 短按 KEY0（<1 s 松开） | 立刻（松开后）切下一张；之后**重新**有 3 s 才自动走 |
| 5 | 短按 KEY1 | 回到上一张；在编号最小的那张上按 KEY1 → 回绕到编号最大的那张 |
| 6 | 长按 KEY0 约 1.5 s 后松开 | **停在当前这张不动**（不切图），数码管整屏 ~2 Hz 闪烁；一直等 10 s 也不自动走 |
| 7 | 暂停期间短按 KEY0 | 照常切图（手动优先），数码管仍闪烁，仍不自动走 |
| 8 | 再长按 KEY0 | 恢复轮播（数码管停止闪烁），**3 s 后**自动切下一张（不是立刻） |
| 9 | 快速连按 KEY0 三下（每下间隔 <0.4 s） | 只有第一次生效，屏幕上只前进 1 张（装载期间按键被忽略），之后从这张起重新计时 |
| 10 | 拔卡上电 | ≈2.7 s 黑屏后显示 M1 测试图案（绿边框 + 红/绿渐变），数码管 `E1`，`led[0]` 灭、`led[2]` 亮；**不会**每 3 s 闪一次 |
| 11 | 卡里只有 TXT | 同样回退图案，数码管 `E3` |
| 12 | 卡里有 1 张非 640×480 的 BMP | 该图被跳过 → 回退图案，数码管 `E4` |
| 13 | 卡里 >16 张 | 只索引前 16 张（MAXF），总数显示 `16` |
| 14 | 只用 1 张图 | 总数 `01`、图号 `0001`；轮播到点会"切到同一张"（重新装载一遍，屏幕不变，数码管 DP 闪一下）|

### 9.2 数码管专项检查（上板第一件事）

| 现象 | 结论 / 处理 |
|---|---|
| 完全全灭 | 先把 `I_busy`/`display` 状态按住 KEY2 复位后应该有 `--`；若一直全灭 → 查 T14/R12/R14 是否约束、595 的 OE/电源（与逻辑无关的部分） |
| 全部 8 位都显示同一个字符、或乱闪 | 位选/段选反了（`{seg,sel}` 顺序），或 SCLK/RCLK 接反；先确认 IO.adc 的三个脚与底板丝印一致 |
| 数字左右镜像（`0001` → `1000`） | `DIG_REV` 置 1，重编译 |
| 只有 2 位亮，其余全灭 | 底板只焊了 2 位；`00xx` 的低 2 位就是图号，属正常 |
| 亮度明显不均匀/发暗 | 扫描 1 kHz + 16 位移位没问题；多半是 595 输出限流电阻与数码管共阳/共阴匹配问题（硬件） |
| 挂载慢（2.7 s） | 无卡超时（M2 R9），数码管此时已是 `E1` |

### 9.3 失败判据 → 先查哪里

| 现象 | 最可能原因 | 检查点 |
|---|---|---|
| 全黑无 HDMI | PLL 没锁 / 复位没释放（M0/M1 老问题） | 量 `S_pll_lock`；按 KEY2 |
| 有画面但按键无反应 | 按键引脚/极性；或正在装载 | 量 `key0_n`(F7) 按下为 0；看数码管 DP 是否常亮（亮 = 正在装载，按键本来就无效） |
| 长按不暂停 | 长按没到 1.000 s（消抖后计时），或 KEY0 引脚 | ChipWatcher 看 `u_video_src/S_hold_cnt`、`S_paused` |
| 轮播不停 | `S_paused` 没翻转 / `has_img` 恒 1 | 看 `u_video_src/S_paused`、`S_himg_sync[1]` |
| 轮播太快/太慢 | `AUTO_FRAMES` 与帧率 | 看 `S_auto_cnt` 的周期是否 179 帧；帧率由 25 MHz 决定（M0 已定） |
| 数码管显示 `E1`/`E2`/`E3` 但画面正常 | 不可能（err 只在失败时非 0）；若出现，说明状态总线被撕裂 → 查过滤器的 1 kHz 节拍（`u_seg7/S_tick`） |
| 数码管图号与画面不一致 | 锁存点不对 | 图号只在 `ready_pulse`（`u_video_src/O_ready_pulse`）锁存；若不一致，看 `S_num` 是否在别的时刻被改（应为 0 处） |
| 切图瞬间数码管闪一下乱码 | 595 帧被中途改写（本设计不应发生） | 看 `u_hc595/S_st` 是否在 `I_start` 时不在 `H_IDLE`（正常应总是 IDLE） |

### 9.4 建议的测量点（ChipWatcher）

`u_video_src/S_paused`、`u_video_src/S_auto_cnt[7:0]`、`u_video_src/S_next_pulse`、

`u_video_src/O_key_next_tog`、`u_fat/S_key_next`、`u_fat/O_key[15:0]`、`u_fat/O_count[4:0]`、
`u_fat/O_err[2:0]`、`u_seg7/S_stat[15:0]`、`u_seg7/S_dig[2:0]`、`u_seg7/O_seg[7:0]`、

## 10. 风险与假设

| # | 假设/风险 | 依据 | 一旦不成立的现象 | 应对 |
|---|---|---|---|---|
| **M3-R1** | 数码管位序按厂商 `HEX8.v` 约定（`sel[0]` = 个位） | 厂商例程 + `hw-facts.md` §8 | 数字左右镜像 | `m3_seg7` 的 `DIG_REV` 置 1（70 s 重编译） |
| **M3-R2** | 底板是 8 位数码管（任务书写的是 2 位） | `hw-facts.md` §8：16 bit = 段 8 + 位 8；`HEX8.v` 8 位扫描；底板图 2 片 595 | 只有 2 位亮 | 右端 4 位就是图号，`01` 依然可读；无需改逻辑 |
| **M3-R3** | 595 段码低有效（共阳数码管） | 厂商 `HEX8.v` 的 `decode` 全部是低有效 | 全亮/全灭但内容"反相" | 把 `SEG7()` 表按位取反（一行） |
| **M3-R4** | 长按 1.000 s 的判定从**消抖后**算起 | 设计如此 | 实际要按 1.01 s 才触发 | 无感差异；要更短就改 `HOLD_CLKS` |
| **M3-R5** | 每张"显示 3.007 s"，墙钟周期 ≈ 3.4 s | 计时器在 ready 重装 | 用户掐表看到 3.4 s | 报告已说明；要"请求周期 3 s"就把 `S_ready_pulse` 从 `S_timer_rst` 里去掉 |
| **M3-R6** | 无卡时不自动轮播 | 有意为之（避免每 3 s 重试挂载） | 插卡后不会自动开始，要按一下键 | 需要"热插拔自动识别"就加：`count==0` 时每 5 s 发一次重试 |
| **M3-R7** | 100 MHz 域 setup 余量 **0.744 ns**（7.4%），但同一份 RTL 的多次编译在 0.15…0.74 ns 之间跳（布局决定） | §7.2 | 极端条件下可能不收敛 | 同 M2 R2：降 SPI 频率 / 拆 u_fat；`arr_filter true` 在本版本 TD 不可用 |
| **M3-R8** | Hold WNS 仍只有 **+14 ps**（M2 时 +3 ps，同一批路径） | 与 M0/M1/M2 同批路径 | 上板偶发像素错 | 同 M2 R3 |
| **M3-R9** | SD 引擎 `spi_clk` 仍无 SDC | M2 R1 | 偶发扇区读错 | 同 M2 R1（降到 12.5 MHz） |
| **M3-R10** | 未上板验证（无硬件） | 本机无板 | — | §9 的 14 条操作 + 6 条专项检查即为上板脚本 |

## 13. 下一步（M4 衔接）

1. **音频**：数码管与按键逻辑已经全部在 25 MHz 域、且不占用 100 MHz 余量，
   M4 加 I2C/I2S 时可以直接用 50 MHz 域的 `clk_50m`（或 PLL 的 C0 100 MHz），
   不会与 M3 的交互逻辑抢资源（当前 LUT 23.9%、FF 21.5%、BRAM 26.6%，余量充足）。
2. **OSD/加载提示**（M3 可选没做）：把 `S_wr_busy` 接到显示侧，在画面角上叠一个"加载中"标记，
   比只靠数码管 DP 更直观（需要给 AXIS 数据加一级覆盖逻辑，风险低）。
3. **上板回归顺序**：数码管段码/位序（M3-R1/R3）→ 按键极性 → 长按阈值手感 → 轮播节奏
   → 连按丢弃行为 → 无卡/无图错误码。
4. **若要"请求周期严格 3 s"**：把 `S_ready_pulse` 从 `S_timer_rst` 里去掉（一行），
   代价是每张的实际显示时间变成 3 s − 0.4 s。
